## 🟢 0. 측정 환경과 방법  

### 🟡 환경  
- Python 3.11, OpenCV(opencv-contrib-python) 5.1.0, NumPy 2.4.6  
- 해상도 640x360, 30 FPS  

### 🟡 테스트 영상  
- 영상은 `tools/make_test_videos.py`로 만든 **합성 영상**이다.  
    - 물체를 프로그램이 직접 그리므로 매 프레임 정답 위치(Ground Truth)를 정확히 알 수 있다.  
    - 영상마다 첫 1초(30프레임)는 배경만 나온다. 배경 모델이 학습할 시간이다.  
    - 카메라 센서 노이즈(표준편차 3)를 매 프레임 더했다.  

| 영상명 | 조건 라벨 | 길이 | 테스트 이벤트 |

| single_move.mp4 | 단일 객체 이동 | 26초 (780프레임) | 화면 왕복 10회 |  
| two_cross.mp4 | 두 객체 겹침 (필수 시나리오) | 26초 | 두 사람이 같은 줄에서 마주 보고 교차 10회 |

### 🟡 측정 방법  
- `tools/evaluate.py`가 정답과 추적 결과를 1:1로 매칭해 자동으로 센다. 정답 중심과 가까운 ID를 Hungarian으로 짝짓는다.  
    - ID Switch: 정답 객체에 붙은 ID가 바뀌고, 바뀐 ID가 **5프레임 이상** 유지되면 1회  
    - 추적 실패: 정답 객체가 화면에 있는데 **10프레임 이상** 연속으로 ID가 없으면 1회  
    - 가림(occlusion): **50% 이상** 가려진 프레임은 추적 실패 계산에서 빼고 비고에 기록  
- 실패율 = ID Switch나 추적 실패가 1건 이상 생긴 테스트 수 / 전체 테스트 수  
- 이 문서의 숫자는 합성 영상 기준이다. 실제 웹캠 영상에는 사람 형태 변화, 그림자, 카메라 자동 노출 같은 요인이 더해지므로 실제 촬영 영상으로 다시 측정해 이 표 옆에 추가해야 한다.

## 🟢 3. 배경 모델링의 한계  

### 🟡 학습률에 따른 동작 차이  

(SW = ID Switch, FAIL = 추적 실패, ID = 생성된 ID 수. 이상적인 값은 단일 이동, 일시 정지, 조명 변화 모두 ID 1개)  

| 방식 | 학습률 | 단일 이동 | 일시 정지 | 조명 변화 |  
| --- | --- | --- | --- | --- |  
| MOG2 | auto | SW 0 / FAIL 0 / ID 1 | SW 4 / FAIL 5 / ID 5 | SW 1 / FAIL 1 / ID 3 |  
| MOG2 | 0.001 | SW 0 / FAIL 0 / ID 1 | SW 0 / FAIL 0 / ID 1 | SW 2 / FAIL 1 / ID 7 |  
| MOG2 | 0.01 | SW 0 / FAIL 0 / ID 1 | SW 4 / FAIL 5 / ID 5 | SW 0 / FAIL 1 / ID 1 |  
| MOG2 | 0.1 | SW 0 / FAIL 1 / ID 0 | SW 0 / FAIL 1 / ID 0 | SW 0 / FAIL 1 / ID 0 |  
| absdiff | 0.001 | SW 4 / FAIL 6 / ID 5 | SW 0 / FAIL 1 / ID 1 | SW 1 / FAIL 3 / ID 5 |  
| absdiff | 0.01 | SW 4 / FAIL 6 / ID 5 | SW 3 / FAIL 5 / ID 6 | SW 9 / FAIL 9 / ID 53 |  
| absdiff | 0.1 | SW 4 / FAIL 6 / ID 5 | SW 3 / FAIL 5 / ID 5 | SW 5 / FAIL 9 / ID 44 |  

### 🟡 "느린 변화"와 "빠른 변화"의 트레이드오프  
- 학습률이 느리면(0.001): 3초 멈춘 사람을 끝까지 전경으로 잡는다(일시 정지 완벽). 대신 조명이 바뀌면 바뀐 배경을 늦게 배워서 ID가 7개까지 늘어난다.  
- 학습률이 중간이면(0.01): 조명 변화는 빨리 회복한다(ID 1개). 대신 3초 멈춘 사람도 배경으로 흡수되어 5번 모두 사라졌다가 새 ID로 다시 나타난다.  
- 학습률이 빠르면(0.1): 움직이는 사람까지 배경으로 흡수해 아무것도 감지하지 못한다(ID 0개).  
- 결론: "멈춘 물체를 지키는 것"과 "변한 배경에 빨리 적응하는 것"은 학습률 하나로 동시에 만족시킬 수 없다. 배경 모델은 "변한 것이 물체인지 배경인지" 구분하지 못한다. 오직 "얼마나 오래 그대로였는지"만 본다.  
- MOG2 `auto`는 처음에는 1/프레임수라는 큰 학습률로 시작해 점점 느려진다. 이 영상 길이(780프레임)에서 일시 정지 결과는 0.01과 같았다(SW 4 / FAIL 5).  
- absdiff는 픽셀마다 "평소 흔들림 정도(분산)"를 모르고 흑백 밝기 차이에 고정 임계값(30) 하나만 쓴다. 단일 이동 영상에서 absdiff는 780프레임 중 260프레임에서 물체를 하나도 감지하지 못했다(MOG2는 준비 구간 30프레임뿐). 그래서 학습률과 상관없이 ID가 5개로 끊겼다.  
    - 흑백으로 바꾸면 "파란 옷"과 "비슷한 밝기의 배경"이 구분되지 않는다. 컬러로 비교하는 MOG2와의 차이가 이것으로 보인다(추정).  

### 🟡 조명 변화 시 발생하는 문제  
- 첫 급변(frame 105, 밝기 x1.45) 직후 약 20프레임 동안 화면의 100%가 전경으로 판정됐다. 화면 대부분을 덮는 덩어리는 면적 필터(화면의 50% 초과 무시)에 걸려 감지 결과가 0개가 됐고, 그동안 추적이 끊겼다.  
- 이후 4번의 급변(x0.75, x1.35, x0.65, x1.0)에서는 실패하지 않았다. MOG2가 첫 급변 때 픽셀별 분산을 크게 학습해서 이후 변화에 둔감해진 것으로 추정한다(직접 증명하지 않은 가설). 둔감해진다는 것은 진짜 물체에 대한 민감도도 같이 떨어진다는 뜻이다.  
- 배경 모델 입장에서 "조명 때문에 모든 픽셀이 밝아진 것"과 "화면 가득 물체가 들어온 것"은 구분되지 않는다.

## 🟢 4. 거리 기반 추적의 본질적 한계  

### 🟡 왜 겹침 상황에서 ID Switch가 발생하는가  
- 두 사람이 겹치면 배경 차분은 하나의 덩어리만 돌려준다. 이 순간 감지 결과는 1개, ID는 2개다.  
- 합쳐진 덩어리는 한 ID에만 매칭된다. 다른 ID는 마지막 위치에 멈춘 채 "안 보임" 상태가 된다.  
- 다시 갈라지는 순간 두 덩어리는 화면 중앙의 거의 같은 지점에서 출발한다. 두 ID 모두 두 덩어리와의 거리가 비슷해서, "가장 가까운 것끼리 짝짓기"로는 누가 누구인지 결정할 근거가 없다.  
- 이 시나리오에서는 교차 10번 모두 ID가 뒤바뀌었다(ID Switch 20건 = 10회 x 2명).  

### 🟡 규칙을 추가해서 해결하려 했던 시도와 결과  

| 설정 | ID Switch | 추적 실패 | 추적 유지율 | 생성 ID 수 | 단일 이동 부작용 |  
| --- | --- | --- | --- | --- | --- |  
| 기본 (distance, greedy, d=80) | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| 거리 임계값 축소 d=40 | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| 거리 임계값 확대 d=150 | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| ID 유지 시간 축소 max_disappeared=3 | 15 | 0 | 0% | 12 | SW 0 / FAIL 0 |  
| ID 유지 시간 확대 max_disappeared=40 | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| Hungarian 매칭 | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| IoU 매칭 (greedy) | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| IoU 매칭 (hungarian) | 20 | 0 | 0% | 2 | SW 0 / FAIL 0 |  
| 칼만 필터 (greedy) | 4 | 0 | 80% | 2 | SW 0 / FAIL 0 |  
| 칼만 필터 + Hungarian | 4 | 0 | 80% | 2 | SW 0 / FAIL 0 |  
| 칼만 + Hungarian + max_disappeared=40 | 4 | 0 | 80% | 2 | SW 0 / FAIL 0 |  

(추적 유지율 = ID Switch와 추적 실패가 없었던 교차 테스트 비율)  

- 거리 임계값 조정: 효과 0. 교차 직후 두 덩어리는 두 ID 모두와 가까워서, 임계값을 어떻게 잡아도 둘 다 후보가 된다.  
- ID 유지 시간 축소: Switch가 20에서 15로 줄었지만 ID가 12개로 늘었다. "바뀐 ID"가 "새 ID"로 바뀌었을 뿐 문제는 그대로다.  
- Hungarian: 효과 0. Hungarian은 "전체 거리 합"을 최소화할 뿐, 거리 정보 자체가 틀렸을 때는 고쳐주지 못한다. 객체가 2개뿐이면 Greedy와 결과가 거의 같다. 무작위 비용 행렬 2000개에서는 Greedy가 17.5%(349개)에서 최적보다 나쁜 조합을 골랐다. 객체가 많고 촘촘할수록 Hungarian의 이점이 커진다.  
- IoU 매칭: 효과 0. 겹친 박스는 두 객체 모두와 IoU가 높아서 거리와 똑같은 모호함이 생긴다.  
- 칼만 필터: 유일하게 효과가 있었다(20 → 4). "계속 같은 방향, 같은 속도로 움직일 것"이라는 예측으로 갈라진 덩어리를 올바른 쪽에 붙였다.  
    - 남은 4건은 교차 #1(frame 30~104)과 #7(frame 480~554)에서 2건씩 생겼다. 이 합성 영상의 교차 구간은 등속 직선 운동인데도 실패했다. 원인(덩어리 중심 흔들림, 속도 추정 오차 등)은 이번 실험에서 따로 분리하지 않았다.  
    - 이 개선도 "등속 운동"이라는 가정 덕분이다. 실제 사람이 교차 지점에서 멈추거나 방향을 바꾸면 예측 자체가 틀리므로 효과가 줄어든다(이번 영상에서는 측정하지 않음).  

### 🟡 결론  
- 위치, 거리, 겹침, 속도는 모두 "어디에 있는가"에 대한 정보다. 두 객체가 같은 자리에 있는 순간에는 이 정보가 똑같아진다.  
- 파란 옷과 주황 옷처럼 사람 눈에는 명확히 다른 두 객체를, 우리의 추적기는 "색"이나 "모양"을 전혀 보지 않으므로 구분하지 못한다.  
- **위치만으로는 객체를 구분할 수 없다.** 규칙을 아무리 추가해도 "누구인지"에 대한 정보가 없으면 근본적으로 해결되지 않는다.

## 🟢 5. Hand-crafted Feature의 한계  

### 🟡 ORB/SIFT가 회전과 가림에 취약한 이유  
- 회전  
    - ORB는 특징점 주변 밝기의 "무게중심 방향"으로, SIFT는 "기울기 방향 히스토그램의 최댓값"으로 방향을 정해서 회전을 보정한다.  
    - 이 방향 추정은 픽셀 격자(계단 현상), 보간, 노이즈 때문에 회전 후 조금씩 틀어진다. 방향이 틀어지면 설명자(descriptor)가 달라져 매칭이 깨진다. 30도 회전에서 ORB 매칭률이 77% → 53%로 떨어졌다.  
- 가림  
    - 특징점은 "점 하나 주변의 작은 패치"만 본다. 가려진 부분의 특징점은 그냥 사라진다.  
    - 50% 가림에서 ORB 매칭률은 22.6%다. 단순히 절반이 사라진 것(약 38% 기대)보다 더 떨어졌다. 가림 경계에 새로 생긴 모서리가 가짜 특징점을 만들고, 경계 근처 특징점의 설명자도 오염되기 때문으로 보인다(추정, 따로 측정하지 않음).  
- 크기  
    - 50% 축소에서 ORB 매칭률은 5.6%까지 떨어졌다. 탐지 기준(인라이어 12개)에 겨우 걸렸다.  
    - 특징점이 부족해서가 아니다. 장면 속 물체 영역에서는 여전히 474개(원래 크기 1024개)의 특징점이 나왔다. "같은 점"으로 매칭되지 않을 뿐이다.  
    - ORB는 1.2배 간격 8단계 피라미드로 크기 변화를 다룬다. 50% 축소된 물체와 짝이 되려면 등록 이미지의 약 4단계 아래(96x72 크기)에서 같은 점이 나와야 한다. 등록 이미지가 작은데 가장자리 31픽셀은 특징점을 뽑지 않으므로, 그 단계에서는 대응할 점이 거의 남지 않는다(추정). SIFT는 같은 조건에서 45.8%를 유지했다.  

### 🟡 "학습되지 않은 특징"이 새로운 상황에 일반화되지 못하는 이유  
- ORB/SIFT의 규칙("밝기 비교 256번", "기울기 방향 8칸 히스토그램")은 사람이 정한 고정 공식이다. 데이터를 보고 바뀌지 않는다.  
- 그래서 공식이 예상한 변화(회전, 밝기)에는 어느 정도 버티지만, 예상하지 못한 변화(가림, 큰 크기 변화, 모양 변형, 다른 시점, 흐림)에는 대응 방법이 없다.  
- 또한 특징점은 "이 무늬의 이 모서리"를 기억할 뿐 "이건 포스터다"라는 개념이 없다. 같은 종류의 다른 물체, 무늬 없는 물체, 사람처럼 형태가 계속 변하는 대상은 애초에 등록 이미지와 1:1 대응하는 점이 없다.

## 🟢 6. 딥러닝이 필요한 이유  

### 🟡 "객체의 외형을 학습한다면 겹침 문제가 해결될까?"  
- 상당 부분 해결된다. 4번에서 실패한 이유는 "파란 옷 / 주황 옷"이라는 외형 정보를 쓰지 않았기 때문이다.  
- 외형 임베딩(Re-ID 특징, 예: DeepSORT 계열)을 쓰면 교차 직후 "거리는 비슷하지만 외형은 파란 옷과 닮았다"로 판단할 수 있다. 위치 정보가 모호해지는 순간에 다른 종류의 정보를 쓰게 되는 것이다.  
- 다만 완전히 가려진 구간, 같은 옷을 입은 두 사람처럼 외형도 비슷한 경우는 여전히 어렵다. 그래서 실제 시스템은 외형 + 칼만 예측을 함께 쓴다.  

### 🟡 "다양한 변형을 학습한다면 특징점 매칭이 개선될까?"  
- 개선된다. 회전, 가림, 크기, 조명 변화를 데이터로 보여주며 학습한 특징(예: SuperPoint/SuperGlue, LoFTR 계열)은 "어떤 변화는 무시해야 하는지"를 데이터에서 배운다.  
- 5번에서 본 50% 가림과 50% 축소 같은 큰 하락은 공식이 그 변화를 예상하지 못해서 생겼다. 학습 기반 특징은 학습 데이터에 그런 변화가 있으면 그것에 강해진다.  
- 반대로 학습 데이터에 없던 종류의 변화에는 학습 모델도 약하다. 그래서 "무엇을 학습시키는가"가 핵심이 된다.  

### 🟡 "환경 변화를 학습한다면 배경 모델링이 강건해질까?"  
- 강건해진다. 3번의 근본 문제는 배경 모델이 "변한 이유"를 모르고 "얼마나 오래 그대로였나"만 본다는 점이다.  
- 사람이나 자동차를 직접 인식하는 탐지 모델(예: YOLO 계열)은 배경을 학습하지 않는다. "이 모양이 사람인가"를 판단한다. 그래서  
    - 멈춘 사람도 사람으로 계속 탐지한다(일시 정지 문제 해결).  
    - 화면 전체가 밝아져도 사람 모양이 아니면 탐지하지 않는다(조명 문제 완화).  
- 이번 과제에서 학습률 하나로는 "정지"와 "조명"을 동시에 해결할 수 없다는 것을 표로 확인했다. 이 트레이드오프를 벗어나려면 "무엇이 물체인가"를 아는 모델이 필요하다.  

### 🟡 최종 결론  
- 고전적 컴퓨터 비전은 조건이 단순할 때 빠르고 정확하다. 이 구현은 단일 객체 이동 0실패, 정면 특징점 매칭 77~80%, 처리 속도 수백 FPS를 냈다.  
- 하지만 실패한 지점(겹침, 정지, 조명, 가림)은 모두 "의미"를 몰라서 생긴 실패다. 위치, 밝기 변화, 고정 공식은 "이것이 무엇인지"를 알려주지 못한다.  
- 데이터로부터 외형, 변형, 환경 변화를 배우는 딥러닝 접근이 필요한 이유가 여기에 있다.
